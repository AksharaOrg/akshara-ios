# Typing responsiveness implementation and validation

Implemented on 2026-10-11, retaining iOS 16 support and the existing touch commit timing. Changes are local commits; TestFlight distribution and physical-device acceptance remain pending.

## Behavior and safety

- Each key/delete/suggestion operation owns a lazy document-context snapshot. Repeated reads, including nil values, are reused only within that operation. Proxy insert/delete/caret movement and host callbacks invalidate it. Rewrite deletion loops obtain fresh context after each delete. Active composition still validates the host on every keystroke, including immediate Send/reset and field-switch cases.
- Plain English insertion derives capitalization and suggestion context from a validated snapshot plus the insertion. Selection, spacing changes and synchronous host callbacks force authoritative reads. Session traits and frequent preferences are cached and refreshed at their existing presentation/settings/host-change boundaries.
- Sinhala correction runs independently of the suggestion rail on a dedicated serial latest-request worker. An evaluation computes spelling suggestions and the conservative unique replacement together. Space/punctuation only consumes an already-ready result matching document, composition generation, word, mode, language and protected-word revision. An unavailable result commits as typed immediately. No later replacement occurs. Undo and rejection behavior remain intact.
- Suggestions use retained labels and one coalesced rendering pass. The existing 120 ms idle threshold permits a short whole-label fade; Reduce Motion disables it. Labels and selection metadata update together. Character previews are retained and their paths are cached by geometry. Pending composition updates only its previous/current keys. Stable hit geometry is separate from prediction weights. Ordinary letters still update Shift in place.
- Ranking has one active and one replaceable pending request, with the existing 25 ms debounce. Cancellation runs inside scans and next-key evaluation; cancelled partial results never enter caches. Learning is separate from ranking. Persistence snapshots under a short model lock and serializes/waits for disk locks outside that lock. Saved revisions cannot clear newer learning, and reset generations reject older snapshots.
- Bundled bigram byte ranges and correction deletion postings use versioned binary sidecars with SHA-256 source and payload hashes. Loaders validate versions, ranges, entry IDs and file completion, then fall back to the original background loaders on missing/stale/corrupt data. Canonically equivalent bigram groups preserve the original last-group behavior. Original corpora, scoring limits and personal-data formats remain unchanged. Decoded bigram contexts have a bounded 32-entry cache.
- Sinhala emoji prefix lookup uses a Unicode-scalar sorted index with the same shortest-token/lexical tie-breaking. Emoji-picker search runs on its own latest-request worker with a 25 ms debounce and query generations. Clipboard notifications and the existing 750 ms polling timer coalesce capture requests, deferring during typing until 250 ms idle; opening the panel captures immediately. Dismissal/host changes invalidate deferred work. UIKit, Full Access and secure-field checks remain on the main thread.

## Reproduce automated validation

From the repository root:

```sh
zsh Scripts/test_sinhala_predictions.sh
AKSHARA_SWIFT_OPTIMIZATION=-O zsh Scripts/test_sinhala_predictions.sh
swift Scripts/build_prediction_sidecars.swift AksharaKeyboard/Resources --check
zsh Scripts/benchmark_keyboard_runtime.sh
```

For restricted environments, point `CLANG_MODULE_CACHE_PATH` and `SWIFT_MODULECACHE_PATH` to writable temporary directories. The benchmark always compiles with `swiftc -O`, uses isolated temporary defaults/resources, and removes them afterward. Corpus-generator scripts regenerate the paired sidecars; `--check` compares generated bytes without writing files.

The expanded regression suite passed both unoptimized and optimized runs. It covers context-read counts and mutation/callback invalidation; bounded latest-request scheduling; stale/unavailable correction identities independent of rail visibility; cancellation during scans and next-key evaluation; blocked persistence, newer learning revisions and reset races for both languages; indexed/fallback prediction fixtures and 1,536 typo evaluations; stale/corrupt sidecars; 600 Sinhala emoji prefix comparisons; keyword tokenization, ranking and tone deduplication. Existing composition, grapheme/scalar deletion, nil context, spacing, selection, capitalization, English resources, undo/rejection, learning and field-reset fixtures still pass.

A Release simulator compile of the app and extension passed with code signing disabled. Existing UIButton deprecation warnings remain. A subsequent [simulator typing run](Performance/Simulator-2026-10-11/README.md) exercised 48 actual Wijesekara key events: KeyHandling was 2.86 ms p95 and RailRendering was 0.21 ms p95. This small run does not establish end-to-end latency or device acceptance; all-mode, visual/accessibility and overlapping-touch checks remain incomplete.

## Opt-in device instrumentation

Set `AKSHARA_PERF_TRACE=1` in the keyboard extension process environment before launch/profile. Tracing is disabled otherwise. The logger subsystem is `lk.org.akshara.keyboard`, category `Performance`. Key mode IDs are 0 Wijesekara, 1 Phonetic, 2 Smart Phonetic, 3 English. Metadata contains identifiers, generations and counts only; no text, words or coordinates are logged.

Intervals cover KeyHandling/DeleteHandling; HostReadBefore/After/Selection and HostInsert/Delete/MoveCaret; CompositionRewrite; CorrectionEvaluation/Preparation; Sinhala/EnglishRanking, NextKeyWeights and model preparation; CandidateLabel/RailRendering/HitGeometry; EmojiSearch; WorkerQueueDelay (including replaced/cancelled pending requests); ClipboardCapture; and Sinhala/EnglishPersistence. Host-call interval counts expose repeated proxy access. Compare nested host wait time separately from extension-owned main-thread work; inspect WorkerQueueDelay with the newest generation. Enable the environment variable in the actual extension process, not just the containing app. Follow [Apple's performance recording workflow](https://developer.apple.com/documentation/os/recording-performance-data).

## Device acceptance and TestFlight gate — unverified

Use Release builds on an older supported iPhone and a current iPhone, native text fields and a messaging app. Compare the baseline to these commits using three runs of at least 500 input events per mode. Exercise Wijesekara, Phonetic, Smart Phonetic and English; predictions/autocorrect/predictive hit areas on/off; Space and Delete; cold first input and warm typing; broad prefixes and full personal models. Record p50/p95/max, host waits, queue delay, first-key time, CPU and peak memory.

Target at least 30% lower p95 in the affected scenario, no greater than 10% regression elsewhere, and initially 8 ms p95 for extension-owned main-thread work excluding host waits. These targets remain unverified.

Correctness/runtime checks must include grapheme- and scalar-based host deletion; nil context; selected text; middle-of-word edits; immediate Send/reset; field switching; long phonetic words; Wijesekara prebase composition; autocorrection undo/rejection; rapid overlapping touches; Sinhala conjuncts/truncation; VoiceOver; Reduce Motion; rotation; Classic/Liquid Glass; clipboard Full Access/secure fields; rapid emoji searches and skin tones.
